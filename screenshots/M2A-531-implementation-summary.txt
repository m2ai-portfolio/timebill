TECHNICAL DETAILS
==============================================================================

Time Precision:
- time.monotonic() for elapsed time (immune to system clock changes)
- time.time() * 1000 for Unix epoch timestamps in milliseconds
- Integer arithmetic for all durations (no float operations)

Data Flow:
1. start_tracking() → captures start time and initializes tracking
2. record_activity() → updates last activity timestamp
3. is_idle() → checks if elapsed time > threshold
4. stop_tracking() → creates TimeEntry with calculated duration
5. get_entries() → returns list of completed TimeEntry objects

State Management:
- _current_project: Currently tracked project name
- _start_time_mono: Monotonic start time
- _start_ts: Unix epoch start timestamp (ms)
- _last_activity_mono: Last activity monotonic time
- _entries: List of completed TimeEntry objects

Edge Cases Handled:
- Zero threshold (any elapsed time is idle)
- None vs 0 distinction in constructor
- Stop without start (returns None)
- Multiple start calls (auto-stops previous)
- Environment variable parsing
